## What's new in 1.5.0

### 1.5.0 in brief
- **Group Statistics** — compare groups of spectra (e.g. treated vs control) with a
  statistical test, on one value per spectrum or along the whole spectrum, with a step-by-step
  tutorial. [Help](help://group_statistics) · [Tutorial](help://group_statistics_tutorial)
- **2D Map: peak-fit maps and endmember unmixing** — maps of a fitted band's position, width,
  height and area, and maps of the purest components of a map.
  [Peak-fit maps](help://map2d#peak-fit) · [Unmixing](help://map2d#unmixing)
- **Methods report for publications** (File menu) — drafts the data-processing paragraph of a
  paper's Methods section, with parameters and references. [Help](help://methods_report)
- **Automatic saving and crash recovery**, and **Open recent** in the File menu.
  [Help](help://user_guide#autosave)
- **All settings in one place** (File › Settings and saved items…), with your saved presets,
  profiles and pipelines. [Help](help://user_guide#settings)
- **Undo / Redo** buttons and **copy / paste of spectra** (Ctrl+C, Ctrl+V).
  [Help](help://user_guide#history)
- **Plots**: a cursor that lists the value of every spectrum, a reversed x-axis, the legend on
  by default, and quick plotting of thousands of spectra. [Help](help://user_guide#cursor)
- **Getting data in**: paste numbers from Excel, open files from Windows, a preview in the
  Import dialog, JASCO .jwb temperature scans and a CD data-quality warning.
  [Help](help://user_guide#import)
- **Faster**: snapshots about 5× smaller and 4× faster to save; several processor cores for
  Automated Baseline, X-axis alignment and bootstrap; fast SOM training. [Details](#faster)
- **Corrected results**: areas and means over a range, area normalization and Malinowski IND
  (2D maps) — numbers can differ from 1.4. [Details](#changed-results)
- **Dark theme** (View › Theme), and a check that the program works on your computer:
  Help › Run tests… [Dark theme](help://user_guide#theme) · [Run tests](help://user_guide#run-tests)

### New
- **Peak-fit maps (2D Map).** Five new Metric entries: *Fitted peak position*,
  *Fitted FWHM*, *Fitted peak height*, *Fitted peak area* and *Fit quality (R²)*.
  In every pixel one band (Gaussian, Lorentzian or pseudo-Voigt) plus a
  background (none, constant or linear) is fitted to the points of the Band
  range.
  - *More precise than the quick metrics.* The quick *Peak position* takes the
    x-value of the highest data point, so it can only jump from one measured
    point to the next (on a Raman map with a point every ~1.9 cm⁻¹: 3332.1,
    3334.0, ...). The fitted position is the centre of the fitted curve and can
    lie between the measured points (e.g. 3333.7), so band shifts smaller than
    the point spacing become visible across the map. Noise and a sloping
    background disturb it much less.
  - *Fit settings…*: peak shape, background, *Hide fits with R² below*,
    *Reject bands narrower than* (spikes, see below), processing and workers;
    remembered between sessions.
  - *Pixels without a value* (the fit failed, its centre ended at the edge of
    the range, or the "band" is wider than the whole range — noise fitted as a
    huge hump) are drawn hatched light grey, in every map type.
  - *Click a pixel* to see its spectrum zoomed to the band with the fitted
    curve, its dashed background, and centre, FWHM and R²; a rejected fit is
    shown as a grey dotted line with the reason.
  - *A noisy first guess does not decide the result.* A rejected fit is
    repeated from two better starting points (taken from a smoothed copy of the
    spectrum) and the best fit is kept.
  - *Spike pixels.* A cosmic ray or single noise point can "win" the fit: a
    curve one point wide that hits the spike matches the data better than a
    weak broad band. With *Reject bands narrower than: 2 / 3 / 4 data points*
    switched on (off by default), such spike fits are set aside and the best
    fit that is not a spike is used; the pixel is left blank only if there is
    none. (Removing cosmic rays before mapping is still the best remedy.)
  - *Map arithmetic with fitted values.* Band A and Band B are fitted
    separately in every pixel and the operation combines the two fitted
    values: e.g. **A / B** of the fitted areas maps the ratio of two bands
    (e.g. lipid / protein) free of the background, **A − B** of the fitted
    positions maps the distance between two bands. Clicking a pixel shows
    both fits (Band A dark blue, Band B dark red).
  - *Fitting starts only with Update Map* (as for SVD/NMF/MCR-ALS): choosing a
    fitted metric, the band, the Fit settings, the map size or type does not
    start it, so several things can be changed first. Switching between the
    five fitted maps afterwards is instant. Progress bar with Cancel.
- **Endmember unmixing (2D Map → Map Type "Unmixing").** Finds the purest
  pixels of a map — their measured spectra are the *endmembers* — and shows
  for each endmember where it is and how much of it every pixel contains
  (abundance maps). Two methods: *VCA* (fast) and *N-FINDR* (more thorough).
  *Suggest number* estimates how many substances the map contains, white
  circles mark the endmember pixels, a *fit-error map* shows where something
  is left unexplained (often: one more endmember needed), the abundances can
  optionally be fractions that sum to 1, and the endmember spectra can be
  added to the spectra list. *Denoise first* (on by default) removes most
  of the noise before the purest pixels are searched, so the endmembers are
  clean spectra rather than noisy single pixels. *Suggest number* shows the
  singular values and offers two numbers: how many components are *clearly
  above the noise* (more than 2× the noise level — a good number to start
  with) and how many are *above the noise* (more than 1.15× — an upper
  limit). *Show all endmembers…* plots all
  endmember spectra at once, stacked or as a grid with their maps. Try it on
  *Help → Test datasets → Synthetic → Endmember unmixing*: a cell made of
  four known substances; the help also shows a real example, the
  Glenodinium map (21 000 spectra).
- **Group Statistics** (Analysis & Visualization → Data Analysis → Group
  Statistics): compare groups of spectra, e.g. treated vs control, with a
  statistical test — on one value per spectrum or along the whole spectrum.
  - *Groups* are typed like in a spreadsheet (fill handle, copy / paste from
    Excel, Delete, Ctrl+Z), set for selected rows, taken from the spectrum
    names (common root name, a text they contain, or a part of the name) or
    from a CSV / Excel table. If the Excel workbook has a sheet **Groups** (or a
    file `<data file>_groups.csv` lies next to the data), the groups fill in by
    themselves. Group cells have the colour of their group in the plot.
  - *The value* of each spectrum: one band (area, baseline-corrected area,
    mean, maximum, peak position, FWHM, fitted peak values, intensity at x —
    also averaged or fitted over x ± w, so one noisy point does not decide it),
    two bands combined (A / B, A − B, log₂(A/B), …), or the whole spectrum
    (PCA score, SVD coefficient, correlation with a reference group).
  - *Tests*: Welch t-test / ANOVA, Mann–Whitney / Kruskal–Wallis, Welch ANOVA
    with Games–Howell (unequal spread), Kruskal–Wallis with Dunn, a
    permutation test, and paired tests (paired t-test, Wilcoxon) for the same
    samples measured twice (e.g. before / after). Every pair Holm-corrected,
    effect sizes with 95 % confidence intervals, checks of the test's
    assumptions with plain advice, possible outliers named, and a results
    sentence ready for a paper. Changing the test recomputes at once.
  - *Replicates done right*: an optional **Sample** column says which spectra
    come from the same sample (cell, map, cuvette). **One value per sample**
    averages them, so the test counts independent samples, not spectra. A
    warning names sample names used by several spectra of one group; paired
    tests say which samples had no partner and were left out.
  - *Spectra tab*: compares the groups at every point of the spectrum (with
    the correction for testing many points), shades the regions where they
    differ, and adds one overall test of the whole spectra (PERMANOVA).
    Optional normalization (to a band, unit area, SNV). Fast also for large
    maps.
  - *2D maps*: ROI → *Compare ROI regions in Group Statistics…* compares
    regions of one map (e.g. nucleus vs cytoplasm).
  - Box, violin or points-with-confidence-interval plots, saved as PNG, TIFF,
    SVG or PDF; export to Excel or CSV with a report sheet. The groups appear in
    the order of the group table (e.g. control, low dose, high dose). *Dots*
    chooses how the dots are spread sideways so they don't cover each other:
    Automatic (a beeswarm, or a density-scaled spread for many values), Random
    jitter, Beeswarm or Density-scaled — always the same picture for the same
    data.
  - Five demo datasets with known answers (Help → Test datasets → Synthetic →
    Group Statistics), a **step-by-step tutorial** (6 lessons) and small
    orange **?** buttons that explain each part of the window.
  - The groups, samples and settings are remembered for the session and
    saved in snapshots; they belong to the spectra, not to their names
    (a renamed spectrum keeps its group; data imported again start fresh).
- **Methods report for publications** (File → Methods report for
  publication): drafts the data-processing paragraph of a paper's Methods
  section for the processing behind the spectra shown, with a parameter table
  and references to the original method papers. Everything is editable; copy
  to Word or save as Word, HTML, Markdown or text.
- **Automatic saving and crash recovery** (File → Automatic saving: off / 5 /
  10 / 20 minutes, default 10). After a crash the next start offers to restore
  the unsaved work. **File → Open recent** lists the last 10 data files and
  snapshots.
- **CD data quality warning.** For JASCO CD data, wavelengths where the
  detector voltage (HT) is above 700 V, or the absorbance above 3.0, are
  shaded grey in the plots and listed after import — the CD signal there is
  unreliable. Limits and shading in View → CD data quality.
- **Import preview**: the import dialog shows a plot of the spectra exactly as
  they will be imported with the current settings, for every file format.
- **Import of JASCO `.jwb` files** (temperature scans, e.g. CD melting).
  Each temperature becomes its own spectrum, named with its temperature,
  so Melting Curve Analysis can use the files directly. Choose CD and/or
  absorbance in the import dialog.
- **Sample CD melting data**: three real scans (two heating, one cooling)
  under *Help → Test datasets → Real (measured) → CD melting (JASCO .jwb)*.
- **Undo / Redo buttons** next to Run: one step back or forward in the
  Operations History.
- **Copy / paste of spectra** like everywhere else: Ctrl+C only remembers the
  selected spectra, Ctrl+V adds the copies.
- **2D Map ROI regions are remembered** when the map is closed and opened
  again, and saved in snapshots (also their Include / Exclude mode and names).
- **Snapshots keep more of your work**: band markers, plot appearance (axis
  titles and fonts, legend, grid lines, layout), Group Statistics groups and
  settings, ROI regions, and the last settings of the processing windows.

### Faster
- **Automated Baseline correction can use several processor cores.** A new
  *Processing* box offers Automatic, Serial or Parallel and the number of
  workers. On a 625-spectrum map the jbcd method went from about 2 minutes
  to about 19 seconds. The results are identical in every mode; the result
  message says how the job was computed.
- **Fast SOM training.** The SOM dialog has a new *Training method*:
  *Online* (the classic method, unchanged and still the default) or *Batch*,
  which trains in seconds instead of minutes (1.4 s instead of about 77 s
  for 625 spectra). Batch is a different algorithm, so its map differs
  slightly (and may be rotated or mirrored); the SOM help explains how to
  compare them.
- **Snapshots are about 5× smaller and 4× faster to save.** Before, a snapshot
  was one compressed *text* file in which every number was written out as
  text (base64), every spectrum carried its own copy of the x-axis, and every
  step of the Operations History stored all spectra again — also the ones the
  step did not change. Now a snapshot is a ZIP file with the numbers stored
  as plain binary, every distinct array stored only once (a shared x-axis,
  spectra a step left unchanged), and 64-bit numbers stored as 32-bit when
  that is exactly lossless. Example, a 21 000-spectrum map with two
  processing steps: 1.36 GB in about 70 s before, about 280 MB in about 18 s
  now. Older snapshots still open; snapshots saved by 1.5 cannot be opened by
  1.4 or older.
- **Parallel processing uses all processor cores by default.** *Workers* is
  a slider from 1 to the number of cores, showing e.g. "20 / 20 (max)".
  The free memory is only shown as a hint (an orange note when it suits fewer
  workers); if the workers ever run out of memory, the job is redone serially
  with the same result.
- **Progress bars move smoothly in parallel mode** (Automated Baseline,
  peak-fit maps): every spectrum is counted as soon as it is done, so the bar
  moves steadily during the whole job.
- **Tool windows open quickly with thousands of spectra.** FFT Denoising with
  all 21 000 spectra of a map selected opened in about 58 s, now in about
  3.5 s; X-axis alignment in about 2 s. Tool windows (FFT Denoising, X-axis
  alignment, Isosbestic points, 2D Correlation, Normalization, Data range,
  Spectral Calculator, ROI spectra) draw at most 100 spectra, evenly spread
  (the plot says e.g. "100 of 3 000 shown"); their calculations always use all
  of them. The number is set in View → Plotting many spectra….
- **X-axis alignment can use several processor cores** (*Processing* and
  *Parallel workers*, as in Automated Baseline); same shifts in every mode, and
  a line under the progress bar says how the job ran.
- **Bootstrap uncertainty is faster.** NMF and MCR-ALS compute the resamples
  on several processor cores (same result; a very large table such as a whole
  map is computed in one process, so the computer does not run out of
  memory), and NMF / MCR-ALS fits of large tables are up to about 3.5× faster
  (one NMF resample of 5 000 spectra: 4.5 s → 1.3 s). The SVD Analysis
  and PCA bootstrap compute only the components they need (on a 20-core PC
  about 40 s → 16 s), and SVD Analysis suggests the number of components above
  the noise (13 for a Raman map, instead of 472 for 95 % of the variance).
- **SVD background correction** of a large table (e.g. a whole map) opens at
  once and shows "Computing the SVD of … spectra" while it works (before,
  nothing happened for about 10 s).

### Easier to use
- **Plotting thousands of spectra stays quick.** The Overlay, Grid and Waterfall
  plots draw at most 1 000 spectra; with more selected, a preview of 1 000
  evenly spread spectra (the selection itself is unchanged — analyses use all
  of them). *Plot all* draws everything, the Overlay plot in portions with a
  progress window and *Stop*, which keeps what is drawn and switches
  Interactive Update off. The number is set in View → Plotting many spectra….
- **The legend is on by default** and stays quick and readable with many
  spectra: it lists at most 20 entries (☰ Legend → Maximum Legend Items),
  evenly spread over the selection, and the strip above the plot says so with
  *Show all*, *Choose…* (pick the spectra listed) and *Settings…*. Show or hide
  it with the new **show legend** checkbox in *Basic plot options*.
- **How many components? SVD Diagnostics shows the noise.** The singular-value
  plot of SVD Analysis and of the 2D Map shows the noise level (a line fitted
  to the flat end of the curve), the noise limit and the components clearly
  above the noise, and the Summary lists both numbers — the same as *Suggest
  number* in Unmixing. 2D Map → SVD → *Diagnostics…* opens in its own window.
- **Dividers (splitters) move smoothly.** Between the controls and the plot of
  Manual / Automated / SNIP baseline, SVD background, X-axis alignment,
  Resolution enhancement and Isosbestic points the divider used to jump between
  "full" and "hidden"; now it moves gradually, the controls scroll when narrow,
  and no part can be dragged away completely (also in SVD interpolation,
  Spectral Calculator, 2D Map, Reference Matching and Group Statistics). New
  dividers in Interactive subtraction and Spike removal.
- **Cursor in the plot.** Tick *Cursor*: a vertical line follows the mouse and a box lists x and
  the value of every drawn spectrum there. Click to pin cursors; right-click → *Copy cursor
  values* copies them as a table for Excel.
- **Paste numbers from Excel or a text file** (File → Paste data from clipboard, Ctrl+Shift+V):
  x in the first column, one spectrum per further column, optional header row, decimal comma or
  point. Tables with one spectrum per row are recognised too, also a whole spectrometer export
  (e.g. a Specord CSV with No., Type, Name, Date … before the wavelengths). After each paste a
  message says how the table was read; when the guess is wrong, use the Import dialog, where you
  choose the layout yourself.
- **Open files from Windows**: double-click a snapshot (.snapx) to open it; *Open with →
  SpecAnalytiXBase* for data files; file names can also be given on the command line.
- **Dark theme** (View → Theme, from the next start); plots stay white.
- **Help → Run tests…** checks that the program works on your computer (about 1300 tests,
  5–10 minutes, in the background) and saves one file to send to the developer.
- **Reversed x-axis**: tick *reverse x* (Basic plot options) to draw x from high to low, e.g.
  4000 → 400 cm⁻¹ for IR and Raman spectra — in every plot type and in Open in New Window.
- **All settings in one place** (File → Settings and saved items…): everything the
  program remembers on this computer, changed directly in the table and reset one by one
  or all at once; the orange **?** explains each setting. A second tab lists your saved
  items — normalization presets, import profiles, batch pipelines, Open recent and
  automatic saves — which are deleted only when you choose, never by a reset, and the
  folders where everything is kept.
- **One Parallel processing setting for all tools**: Automated Baseline, X-axis
  alignment, the peak-fit maps and bootstrap uncertainty start from the same choice
  (e.g. *Serial* to keep the computer free for other work), set in File → Settings
  and saved items….
- **Tool windows remember the selected spectra.** Normalization, Combine
  Spectra and Data range open with all spectra selected; the spectra you
  select are selected again the next time you open the same window (until the
  program is closed) — also in FFT Denoising, X-axis alignment, Isosbestic
  points and Interactive subtraction.
- **Help explains the calculations**: figures in the helps show how areas over
  a range are computed and what happens with spectra that have different
  x-axes or intensity scales.
- **Automatic saving never slows you down.** It waits while an operation is
  running, writes the file in the background with a note in the status bar,
  and saves only when something changed. At every interval it compares a
  fingerprint of everything — data, Operations History, selection, plot and
  other settings, metadata — with the last automatic save, so no change is
  missed or saved late; on a 21 000-spectrum map this check takes well under
  a second. A snapshot you save yourself (File → Save) always contains the
  complete current state.
- **Progress bar and Cancel** for long Automated Baseline jobs and for SOM
  training. Cancelling changes nothing; a SOM map you already had stays
  as it was.
- The SOM progress window shows **an estimate of the remaining time**.
- No more **flickering windows** during long baseline jobs.

### Changed results
Corrections: some numbers can differ from 1.4.

- **Areas and means over a range** (2D Map, Band Ratio, Group Statistics) now
  run exactly from the start to the end of the range. Before, they started
  and ended at the first / last measured point inside it (e.g. about 11 %
  too small for a 27 cm⁻¹ range on a Raman map), and with several ranges the
  gaps between them were bridged and counted (up to about 9× too large). The
  mean is now area ÷ width (correct for unevenly spaced points); the
  baseline-corrected area uses a line through the values at the range edges.
- **Normalization – Area** uses the same exact areas; **Offset correction**
  uses the mean height over the region. A spectrum that the region does not
  completely cover is now left unchanged and named (before it was quietly
  normalized by the part it had).
- A spectrum that does not completely cover a range gets **no value** (blank
  pixel, "—" or left out and named) instead of a misleading smaller value.
- **Peak Fitting**: the area of a Voigt peak is now exact (before up to 0.6 %
  too small).
- With evenly spaced data and range edges on measured points nothing changes.
- **Data range with *Apply linearization*** no longer invents values outside a
  spectrum's measured range. Before, a spectrum that did not cover the whole
  X-min – X-max range was extended there by the spline, often with absurd
  values. Now it gets new points only where it was measured (it is named in
  the message), and all spectra share the same x-values.
- **Malinowski IND** (how many components to keep; SVD Analysis, 2D Map, PCA,
  SVD background, SVD interpolation) was wrong for tables with more spectra
  than points, i.e. 2D maps: Malinowski's formula uses the *smaller* side of
  the table, the program always used the number of spectra. For a map of
  21 000 spectra × 1 600 points the IND minimum was at 1599 components; now it
  is at 9. Smaller corrections: IND was off by one, the residual error of a map
  used the wrong number of spectra, and in PCA the residual error and IND
  depended on how many components were requested.

### Fixed
- *Open in New Window* failed for every plot type with current matplotlib.
- In Map arithmetic, a second, unused "Configure Band A…" button appeared
  after changing the metric.
- The "reverse sorting" option was not saved in snapshots.
- Spectra added by a later import seemed to come and go when jumping in the
  Operations History, and the import could not be undone. Such an import is
  now its own "Import" step (Undo removes the spectra, Redo brings them back).
- Spectral Calculator no longer creates undefined values silently (log or
  square root of negative values, division by zero) — it says why instead.
- SNIP baseline, Melting Curve automatic fit, NMF, PLS and Cosmic ray removal
  no longer fail on unusual data (very short spectra, a flat curve,
  identical spectra, a single spectrum).
- Changing **X-scale, Y-scale or Link axes** with an Overlay or Grid plot on screen did not
  redraw the plot (the setting only took effect at the next redraw). It now redraws at once.
- The **Grid plot** ignored X-scale and Y-scale; every panel now uses them.
- Melting Curve Analysis could freeze the program on Windows when a baseline
  window held only points at temperature 0 (e.g. spectra without a real
  temperature). It now says that the baseline cannot be fitted.
- 2D Map → SVD → *Diagnostics…* failed with "Singular matrix"; the same error
  can no longer occur in any window whose plot is squeezed to zero size.

### Safer
- **Saved normalization presets, import profiles and batch pipelines can
  no longer be lost.** Before, a file damaged by a crash during saving was
  silently replaced at the next save, losing every earlier item. Now saving
  can't leave a damaged file, and an unreadable file is kept as a copy.
- When an operation fails, the **full error details now go to the log file**,
  so problems can be diagnosed.
- A failed SOM run no longer leaves the dialog in a mixed state.
- An unexpected error now shows a message (the program keeps running, so the
  work can be saved) and says where the log file is.

### Upgrading
Install over your existing version as usual. Installers from
1.4.1 onwards remove old library files automatically. Snapshots saved by 1.5
cannot be opened by 1.4 or older — keep that in mind when sharing files with
someone who has not updated yet.
Areas and means over a range, and area normalization, can differ slightly from
1.4, and Malinowski IND and the residual error can differ (a lot for 2D maps) —
see "Changed results".
